# Доработка: дедупликация карточек и стабильность интерфейса

Функциональные правки поверх подготовки репозитория (см. выше). Затрагивают логику поиска
дубликатов при загрузке, связывание обращений из MAX с карточками УСВО и поведение автообновления
веб-кабинета.

## 1. Дубликаты при ЗАГРУЗКЕ данных — по ФИО + телефон + дата рождения

Импорт Excel теперь считает две карточки дублями, только когда совпали **все три** реквизита
сразу: ФИО, дата рождения и телефон. Раньше действовал каскад «или» (ФИО+дата **либо** ФИО+телефон),
из-за чего разные люди с одинаковыми ФИО+датой (но разными телефонами) склеивались, а одинаковые
записи с изменившимся телефоном — наоборот.

- Новая строгая функция ключа `usvo.card_identity_strict(name, birth, phone)` →
  `npb:<фио>|<дата>|<телефон>` (пустые реквизиты сравниваются как равные; без ФИО дубликат не
  определяется). `record_identity_strict` — обёртка над записью.
- `WebService.import_usvo` строит множество `existing` и ключ каждой строки файла через
  `*_strict`. Повторная загрузка того же/пересекающегося файла дублей не плодит; две разные записи
  с одним ФИО+датой, но разным телефоном — обе сохраняются.
- **Каноникализация даты рождения** `usvo._norm_birth` (YYYYMMDD): понимает ISO `1980-05-01`,
  русский `01.05.1980`, форматы со слэшами. Раньше простой «выброс нецифр» путал порядок
  (`01.05.1980 → 01051980` против `1980-05-01 → 19800501`) — одна и та же дата в разной записи
  считалась разной. Применена и в `card_identity` (отображение), и в строгом ключе, и в связывании.
- Подсказка оператору о причине пропуска дубля обновлена: `_dedup_reason` для ключа `npb` →
  «Совпали ФИО, дата рождения и телефон».
- **Отображение-дедуп** (`_all_records`, перекрытие табличной карточки отредактированной) оставлен
  на прежнем «мягком» ключе `record_identity` (ФИО+дата) — правка второстепенных полей карточки
  по-прежнему не разрывает связь «оверрайд ↔ исходная строка».

## 2. Поиск карточки УСВО при обращении из MAX — каскад с обязательным ФИО

`WebService._link_usvo(name, phone, birth="")` переписан как ступенчатый поиск; **ФИО обязательно
на каждой ступени** (строгий матч — минимум два общих значимых токена, `_name_tokens_match`, чтобы
одно общее имя не связывало с чужой карточкой). Берётся первая ступень, давшая совпадения:

1. **ФИО + телефон + дата рождения;**
2. **ФИО + телефон** ИЛИ **ФИО + дата рождения;**
3. **только ФИО.**

- Раньше приоритет был у совпадения телефона **без учёта ФИО** — теперь телефон/дата без совпадения
  ФИО карточку не связывают.
- `link_by ∈ {phone, name, ""}`: если во всех совпадениях подтверждён телефон — «phone» (надёжно),
  иначе (совпадение только по ФИО/дате) — «name» (UI просит проверить номер). Неоднозначность
  (несколько карточек) не выбирается автоматически — оператор выбирает вручную.
- Дата рождения из MAX сейчас недоступна (в профиле `users` её нет) — тогда ступени 1 и «+дата»
  пусты, и каскад корректно вырождается в ФИО+телефон → ФИО. Параметр `birth` заложен на будущее.
- Удалён неиспользуемый `_usvo_matches_by_phone` (матч только по телефону), `_match_usvo_by_name`
  заменён предикатом `_name_tokens_match`.
- Фронтенд `usvoLinkBlock`: заголовок при неоднозначности подписывается честно — «с этим номером
  телефона» либо «с совпадающим ФИО» (по `link_by`).

## 3. Интерфейс переставал «дёргаться»

Причина: фоновый `setInterval` (15 с) вызывал полную перерисовку списка обращений/заявлений —
`renderAppeals()`/`renderApplications()` сначала подменяли всё содержимое скелетоном-заглушкой, затем
перестраивали DOM. Каждые 15 секунд список мигал и «прыгал».

- Добавлен режим **тихого автообновления** `render*({ silent: true })`: без скелетона и без
  перестройки шапки. Считается сигнатура значимого состояния списка
  (`appealsSignature` = id/статус/ответственный/просрочка; для заявлений — id/статус). Если ничего
  не изменилось — **DOM не трогается вообще** (нет мигания). Если изменилось — мягкая замена только
  строк `<tbody>` (раскладка и прокрутка сохраняются), без анимации `fade-in`.
- Строки таблиц вынесены в `appealRowHtml`/`applicationRowHtml` для переиспользования полным и
  тихим путём.
- Интервал: добавлен guard `document.hidden` (не дёргать сеть/DOM в фоновой вкладке); модалка и
  открытая панель по-прежнему приостанавливают автообновление. Ручная кнопка «Обновить» и смена
  раздела работают как раньше (полный рендер).
