# Господдержка СВО — Dify-ассистент + микросервис

Два сценария, реализованные на Dify (`assistant.yml`) и микросервисе (`microservice/`).

## Состав

| Файл/папка | Что это |
|------------|---------|
| `assistant.yml` | Экспорт Dify-приложения (advanced-chat). Импортируется в Dify. |
| `microservice/` | FastAPI-микросервис: извлечение Excel + вся логика MAX-бота + веб-кабинет на `/`. См. `microservice/README.md`. |
| `Информация для базы знаний.txt` | Текст для базы знаний Dify (заносится в датасет). |
| `Spravka_Shablon (1).docx` | DOCX-шаблон справки (плейсхолдеры `{{...}}`). |
| `USVO_..._fixed.xlsx` | Пример таблицы участников. |
| `Ассистент Цифровой Офис.yml` | Образец-референс (не используется в рантайме). |

## Архитектура

```
                         ┌────────────── Dify (assistant.yml) ──────────────┐
                         │  Start (channel, template)                       │
                         │        │                                         │
                         │   Роутер if-else: channel == "max"?              │
   MAX-бот ──────────────┼── true ─→ Поиск в БЗ → LLM(JSON) → Ответ(JSON)   │
   (микросервис)         │                                                  │
                         │   false ─→ HTTP→микросервис /excel/extract       │
   Пользователь Dify ────┼──────────→ Классификатор:                        │
   (загружает xlsx)      │              [1] Вопрос  → LLM → Ответ           │
                         │              [2] Справка → LLM → код → DOCX → Ответ│
                         └──────────────────────────────────────────────────┘
   Excel-файл ─── HTTP ──→ микросервис /excel/extract (компактный текст ≤32k)
   MAX webhook ─── HTTP ─→ микросервис /max/webhook (эскалация, слоты, КБ)
   Оператор ───── HTTP ─→ микросервис / (веб-кабинет: обращения, карточки, аналитика)
```

**Изоляция MAX**: ветка MAX отходит от роутера по `channel == "max"` и физически не связана
рёбрами с ветками задания 1 (Excel/справка) — доступа к ним нет.

## Задание 1 — вопросы по Excel + справка
1. Пользователь загружает `.xlsx` (и, для справки, `.docx`-шаблон в поле «Шаблон справки»).
2. Dify шлёт файл в микросервис `POST /excel/extract` → получает компактный текст таблицы
   (легенда столбцов один раз + записи с индексами, пустые ячейки убраны) — влезает в 32k токенов.
3. Классификатор делит запрос: **вопрос по таблице** (LLM → ответ) или **создание справки**
   (LLM формирует текст → код собирает переменные шаблона → `generate_docx` → файл справки).

## Задание 2 — бот MAX
Вся stateful-логика — в микросервисе (`microservice/README.md`, разделы 7–8). Dify-ветка MAX только
ищет в базе знаний и возвращает JSON `{answer, found_in_kb, confidence}`; решение об эскалации,
inline-кнопки, счётчик 3 вопросов, слоты, чат операторов и запись ответа оператора в БЗ — в боте.

## Импорт в Dify (после деплоя микросервиса)
1. **Создать датасет** и загрузить в него `Информация для базы знаний.txt`.
2. **Импортировать** `assistant.yml` (Studio → Import DSL).
3. В узле **«Поиск в базе знаний (MAX)»** заново выбрать созданный датасет
   (в YAML стоит плейсхолдер `REPLACE_WITH_KB_DATASET_ID`).
4. В узле **«HTTP извлечение Excel»** заменить URL `https://CHANGE-ME-microservice/excel/extract`
   на адрес микросервиса и убедиться, что заголовок `X-Api-Key` совпадает с `server.api_key` конфига.
5. Проверить, что плагин `scibox/document-generator` установлен (узел `generate_docx`).
6. В разделе **API Access** приложения взять ключ `app-…` и вписать в `microservice/config.yaml`
   (`dify.max_app_key`) — им бот вызывает MAX-ветку.
7. Для записи ответов операторов: ключ Knowledge API (`dataset-…`) и `dataset_id` целевой базы
   знаний → в `microservice/config.yaml` (`dify.dataset.*`).

## Запуск микросервиса
См. `microservice/README.md`. Кратко: `pip install -r requirements.txt`, заполнить `config.yaml`,
`uvicorn app.main:app --host 0.0.0.0 --port 8080`. Веб-интерфейс будет доступен на
`http://<host>:8080/`, API — на том же порту.
