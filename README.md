# Господдержка СВО

Контакт-центр господдержки участников СВО и их семей: оркестрация сценариев в Dify
(`dify/*.yml`) и FastAPI-микросервис (`microservice/`), который отдаёт веб-кабинет оператора,
ведёт бота MAX и извлекает данные из Excel.

## Возможности

- **Веб-кабинет оператора** (`/`) — обращения, карточки участников, вопрос-ответ, заявления,
  аналитика с тепловой картой, рассылки и журнал действий; авторизация в стиле ЕСИА.
- **Бот MAX** (`/max/webhook`) — ответы из базы знаний, эскалация оператору, запись на приём,
  пошаговое оформление мер поддержки по фото документов.
- **Извлечение Excel** (`/excel/extract`) — компактная выжимка таблицы участников для LLM
  (укладывается в лимит 32k токенов).

Вся оркестрация LLM и обращения к базе знаний идут через Dify; экспорты приложений — в `dify/`.

## Требования

- Python 3.11+
- Доступ к Dify (для LLM-функций) — опционально: без ключей сервис работает в офлайн-режиме
  на демо-данных и офлайн-нормализаторах.

## Установка

```bash
cd microservice
pip install -r requirements.txt
```

## Конфигурация

Настройки читаются из YAML (не из `.env`). Скопируйте образец и заполните нужные ключи:

```bash
cp config.example.yaml config.yaml
```

`config.yaml` содержит секреты и в репозиторий не попадает (см. `.gitignore`). Все поля
задокументированы в `config.example.yaml`; незаполненные ключи переводят соответствующую
функцию в офлайн-режим, поэтому файл работоспособен «как есть».

Основные секции: `server.api_key` (заголовок `X-Api-Key` для `/excel/extract`),
`dify.*` (ключи приложений и датасета базы знаний), `max.*` (токен бота и способ доставки —
webhook или long polling).

## Запуск

```bash
cd microservice
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

Веб-кабинет: `http://<host>:8080/`. За reverse-proxy кабинет доступен и по подпути
`/application` (роутеры и статика смонтированы дважды).

Настройка и диагностика бота MAX (нужен заполненный `config.yaml`):

```bash
python maxctl.py me                       # проверить токен
python maxctl.py subscribe <https-url>/max/webhook
python maxctl.py poll                      # long polling для localhost без публичного HTTPS
```

## Тесты

Формального фреймворка нет; проверка — компиляция и точечные тесты:

```bash
cd microservice
python -m compileall -q app maxctl.py
python -m pytest tests
```

## Структура

```
dify/                     экспорты Dify-приложений (роутер сценариев, ассистенты)
microservice/
  app/
    auth/                 авторизация кабинета (демо / Ory Kratos)
    common/               общие утилиты (docx, время, health)
    docs/                 меры поддержки, распознавание документов, шаблоны
    excel/                извлечение таблиц участников
    max/                  бот MAX: вебхук, логика, клиент API, состояние (SQLite)
    web/                  веб-кабинет: API, аналитика, история, точный поиск по базе
      static/             фронтенд (HTML/CSS/JS, без сборки)
  data/                   рабочие данные (шаблон, расписание); базы и логи не публикуются
  deploy/kratos/          конфигурация авторизации
  tests/                  тесты
  config.example.yaml     образец конфигурации
  maxctl.py               CLI управления ботом MAX
```

## Развёртывание Dify

1. Создать датасет базы знаний и наполнить его.
2. Импортировать `dify/assistant.yml` (Studio → Import DSL) и остальные ассистенты по мере надобности.
3. В узлах с плейсхолдерами (`REPLACE_WITH_KB_DATASET_ID`, `CHANGE-ME-microservice`) указать
   реальный датасет и URL микросервиса; убедиться, что `X-Api-Key` совпадает с `server.api_key`.
4. Ключи приложений (`app-…`) и Knowledge API (`dataset-…`) вписать в `config.yaml` (`dify.*`).
