# Релиз 2026-07-29 — новый интерфейс веб-кабинета «Контакт-центр»

Веб-кабинет переведён с самописного ванильного фронтенда на сборку
**React 19 + Vite + TypeScript + Tailwind 4 + shadcn/ui** из папки `new_design`.
Бэкенд, MAX-бот и Dify-ассистенты продолжают работать как прежде: изменения в
Python-части точечные и обратно совместимы.

---

## 1. Что изменилось в структуре проекта

| Было | Стало |
|---|---|
| `microservice/app/web/static/{index,login}.html, app.js, styles.css, medals.js` | `microservice/frontend/` — исходники React; `microservice/app/web/static/` — **артефакт сборки** |
| правки интерфейса — прямо в `app.js` | правки — в `frontend/src/**`, затем `npm run build` |
| Leaflet и его CSS с CDN `unpkg` | Leaflet в бандле (кабинет поднимается без внешней сети; тайлы OSM по-прежнему сетевые) |

**Важно:** `app/web/static/` полностью перезаписывается сборкой (`emptyOutDir`).
Руками туда ничего не кладём — статические ассеты (`favicon.svg`, `medals/*`)
живут в `frontend/public/`.

### Команды

```bash
cd microservice/frontend
npm install
npm run build     # обязательно после любой правки frontend/
npm run dev       # dev-сервер :5173, /api и /health проксируются на :8080
npm run lint      # oxlint
npx tsc -b        # типы
```

Проверка бэкенда:

```bash
cd microservice
python -m compileall -q app maxctl.py
python -m pytest tests -q
```

## 2. Новые функции

### Профиль пользователя кабинета
Раздел «Настройки» → «Данные аккаунта»: фамилия, имя, отчество, дата рождения,
телефон.

- Новые эндпоинты `GET/PUT /api/web/auth/profile` (`app/auth/router.py`).
- Хранение — `app/auth/employees.py`:
  - у **сотрудника** (`sub = "emp:<id>"`) профиль лежит в его строке `employees`,
    поэтому новое ФИО сразу видно в списке ответственных за обращение;
  - у **администратора** из `auth.demo_users` / Kratos своей строки в `employees`
    нет — для него заведена таблица `user_profiles` (ключ — `sub`).
- Таблица `employees` расширена колонками `last_name`, `first_name`,
  `middle_name`, `birth_date` — авто-миграция, существующие записи разбираются
  на части однократно (`_backfill_fio`).
- `PUT /profile` **перевыпускает cookie-сессию** с новым отображаемым именем:
  имя лежит внутри подписанного токена, иначе шапка кабинета показывала бы старое
  ФИО до следующего входа.
- `AuthService._apply_saved_profile` подставляет сохранённое ФИО при каждом входе
  — иначе имя из конфига (`auth.demo_users`) перекрывало бы профиль.

### Аналитика: выбор периода и почасовой разрез
- `GET /api/web/analytics?days=<1..92>&end=<YYYY-MM-DD>` — окно графика
  «Динамика по показателям»: **1 день / 7 дней / месяц** с выбором конкретного
  периода. Некорректная дата → 400.
- В режиме «1 день» график переключается на **почасовой** ряд (`series[].hourly`,
  подписи `HH:00`, единицы — `series[].unit_hourly`). Реальные обращения этих
  суток раскладываются по московскому часу поверх детерминированного профиля
  нагрузки (`_distribute_hourly`).
- Настраиваемый макет дашборда (состав и порядок блоков) — сохраняется в
  `localStorage` браузера оператора.

### «ИИ ассистент»: закреплённые диалоги
- `PATCH /api/web/ai-chats/{id}` принимает `pinned`; закреплённые всегда идут
  первыми (`ORDER BY pinned DESC, updated_at DESC`).
- Закрепление **не** двигает `updated_at` — чат не всплывает в «последних»
  только оттого, что его закрепили.
- Колонка `ai_chats.pinned` добавляется авто-миграцией.

### Тёмная / светлая / системная тема
Переключатель в меню аккаунта и в «Настройках» (`next-themes`, ключ `theme`).

### Автоматический полноэкранный режим
`frontend/src/lib/fullscreen.ts`: кабинет разворачивается на весь экран.

> **Ограничение браузера:** `requestFullscreen()` разрешён только внутри
> обработчика пользовательского жеста — вызвать его при загрузке страницы
> нельзя, браузер отклонит запрос. Поэтому переход выполняется по **первому
> клику или нажатию клавиши** в кабинете.

Если пользователь вышел из полноэкранного режима (Esc или средствами браузера),
выбор запоминается в `localStorage` (`fullscreen-auto-off`) и приложение больше
не разворачивает окно — иначе оно отбирало бы управление на каждом клике.
Разметку и стили механизм не трогает.

## 3. Исправления

### Deep-link `/usvo/cards/<id>` ломал загрузку ассетов
Сборка идёт с `base: "./"` (кабинет отдаётся и из корня, и за reverse-proxy по
подпути). На вложенном маршруте `./assets/index.js` резолвился в
`/usvo/cards/assets/index.js` → 404.

`<base href>` эту проблему решает, **но preload-сканер браузера успевает
отправить запросы по статическим `src`/`href` раньше, чем inline-скрипт запишет
`<base>`** — в консоли оставались 404 на каждый deep-link.

Решение — плагин `runtimeBaseAssets` в `vite.config.ts`: теги ассетов, которые
вставил Vite, выносятся в inline-скрипт и пишутся уже с вычисленным префиксом.
Сканеру нечего предзагружать — гонки нет. Проверено: `/usvo/cards/5` и
`/application/usvo/cards/12` грузятся с нулём ошибок в консоли.

### 404 на SPA-маршрутах при перезагрузке страницы
`app/main.py` отдаёт `index.html` на весь список клиентских маршрутов
(`/login`, `/cards`, `/ai-chat`, `/applications`, `/analytics`, `/broadcast`,
`/audit`, `/settings`, `/usvo/cards/{id}`) — каждый зарегистрирован дважды:
напрямую и под `/application`. Раньше сервер знал только `/` и `/usvo/cards/<id>`.

Тест `tests/test_new_design.py::test_spa_routes_match_frontend_router` сверяет
список в `main.py` с `<Route>` в `App.tsx` — разъезд этих списков виден только
как 404 при перезагрузке и в API-тестах не проявляется.

### Статусы УСВО не совпадали с фильтром
В таблице статусы записаны в разном виде (`контракт`, `контрактник`), фильтр
сравнивал строго — из 1500 карточек по «Контрактник» находилось 12, а 495 строк
со статусом `контракт` из выпадающего списка были недостижимы вовсе.

- `usvo.STATUSES` — канонический справочник (`Контрактник`, `Мобилизованный`,
  `Доброволец`, `Ветеран боевых действий`), совпадает с подсветкой бейджей во
  фронтенде.
- `usvo.canonical_status()` приводит известные синонимы к каноничному написанию
  (`контракт`/`по контракту` → `Контрактник`, `ВБД` → `Ветеран боевых действий`),
  нестандартные значения оставляет как есть, пустой статус заменяет на
  `default_status(seq)` — раньше «—» выпадал и из фильтра, и из подсветки.
- `WebService.usvo_statuses()` отдаёт канонический справочник **плюс**
  нестандартные значения, реально встретившиеся в данных, — чтобы карточки из
  чужой выгрузки остались доступны из фильтра.

Результат: 507 / 498 / 495 карточек по трём статусам вместо 12.

### Мигание светлой темы при загрузке
`next-themes` в обычном React-SPA навешивает класс только после гидратации —
тёмная тема успевала мигнуть белым на каждой загрузке. В `index.html` добавлен
блокирующий скрипт, выставляющий тему до первой отрисовки (`storageKey` и
`attribute` синхронизированы с `ThemeProvider`).

### Демо-обращения без текста ответа
У отвеченных демо-обращений вместо ответа стояла заглушка «Ответ направлен
гражданину» — панель ответа и выгрузка в Excel выглядели пустыми. Добавлен
`SEED_ANSWERS` — по одному содержательному ответу на каждый из 12 демо-вопросов.

### Прочее
- `docs/forms.py::_cap` — значения от визуальной модели приходят вразнобой
  (`частное`/`Частное`, `супруга`/`Супруга`), в ячейках заявления теперь
  единообразно с заглавной буквы.
- `web/insight.py` — подписи тональности приведены к мужскому роду
  («Позитивный», «Нейтральный», «Тревожный», «Напряжённый»): в интерфейсе они
  стоят рядом со словом «тон», а не «обращение».
- Медали снова отображаются: фото перенесены в `frontend/public/medals/`
  (сборка кладёт их в `static/medals/`), путь строится от `APP_BASE`.

## 4. Важные технические детали

### Бэкенд НЕ копировался из `new_design` целиком
Python-часть в `new_design` — форк от более раннего коммита. Копирование
«как есть» откатило бы уже сделанную работу, в частности:

- `bot_logic.py` — обработку апдейта `bot_started` (приветствие при первом
  контакте) и кнопку-переключатель подписки на рассылку;
- `web/usvo.py` — строгую идентичность карточек при импорте
  (`card_identity_strict` / `record_identity_strict`, каноникализация даты
  рождения `_norm_birth`);
- `web/service.py` — каскад связи обращения с карточкой УСВО `_link_usvo`
  (ФИО+телефон+дата → … → только телефон как резерв) и пересчёт «раскрытых»
  карточек при удалении.

Поэтому вперёд перенесены **только новые возможности** (профиль, аналитика,
`pinned`, статусы, `SEED_ANSWERS`, SPA-маршруты, `_cap`, подписи тональности).
Сверка выполнена по AST с отброшенными докстрингами: из 52 файлов 39 отличались
только комментариями, реальные изменения были в 13.

Кроме того, в `new_design` сжаты докстринги по всему бэкенду — этот «шум» не
переносился, документация модулей сохранена.

### Дизайн фронтенда — байт-в-байт как в `new_design`
Файлы `app-shell.tsx`, `appeals.tsx`, `cards.tsx`, `index.css` совпадают с
исходными из `new_design` посимвольно. Изменения касаются только сборки и
поведения, не разметки:

- `index.html` — `<base href>` + предустановка темы;
- `vite.config.ts` — плагин `runtimeBaseAssets`;
- `main.tsx` — одна строка вызова `installAutoFullscreen()`;
- `lib/fullscreen.ts` — новый файл, DOM не трогает.

### Совместимость данных
Схемы SQLite расширяются **авто-миграциями** (`_ensure_column`) — существующие
`state.db` и `employees.db` подхватываются без пересоздания и без потери данных.
Новые колонки: `ai_chats.pinned`, `employees.{last,first,middle}_name`,
`employees.birth_date`; новая таблица `user_profiles`.

### Зависимости
- `requirements.txt`: добавлен `eval_type_backport==0.4.0` — нужен pydantic 2 на
  Python < 3.12 для разбора аннотаций вида `str | None` в модулях с
  `from __future__ import annotations` (их в проекте большинство).
- `frontend/package.json`: React 19, Vite 8, Tailwind 4, Radix UI, lucide-react,
  react-router-dom 7, sonner, next-themes, leaflet.
- `.gitignore`: `node_modules/`, `*.tsbuildinfo`, `*.db*`, исключение для
  `RELEASE_NOTES_*.md`.

### Известные ограничения
- **SSO на экране входа — заглушка.** Кнопка «Войти через SSO» показывает
  сообщение «Вход через SSO пока не подключён»: бэкенд использует Kratos как
  парольный провайдер, OIDC-редиректа нет. Реализация требует настроенного
  внешнего IdP и здесь не делалась.
- **Список карточек УСВО рендерится целиком** (1500 строк DOM), без
  виртуализации. Работает, но на слабых машинах первая отрисовка заметна —
  точка для будущей оптимизации.
- Бандл — один чанк ~610 КБ (185 КБ gzip). Vite предупреждает о размере;
  код-сплиттинг не настраивался.
- Тайлы тепловой карты (OpenStreetMap) требуют сети; без неё видны только
  маркеры и heat-слой на сером фоне.

## 5. Что проверено

**Автотесты:** 56 pytest (38 существовавших + 18 новых в
`tests/test_new_design.py`), `tsc -b` без ошибок, `oxlint` — только два
предупреждения о fast-refresh в dev-режиме.

**Вручную, на живом сервисе (uvicorn + браузер):**

- вход администратора и сотрудника; 403 для сотрудника на `/audit` и
  `/settings/employees`;
- профиль: чтение, сохранение, обновление имени в шапке, сохранение имени после
  перелогина;
- CRUD сотрудников; созданный сотрудник появляется в списке ответственных;
- обращения: список, группировка, SLA-бейдж «Просрочено», назначение
  ответственного, отправка ответа, история обращений гражданина;
- карточки УСВО: список 1500 записей, фильтр по статусу, карточка по deep-link
  `/usvo/cards/5` и `/application/usvo/cards/12`, предложения ИИ, фото медалей,
  выгрузка в DOCX;
- аналитика: сводка, переключение 1 день / 7 дней / 30 дней, почасовой график,
  карта Leaflet с тайлами;
- ИИ-ассистент: создание чата, закрепление/открепление, порядок в списке,
  удаление;
- заявления и меры поддержки; рассылки; журнал действий; настройки SLA;
- выгрузки Excel: `usvo` (177 КБ), `appeals`, `applications`, `analytics`;
- все SPA-маршруты отдают 200 при прямом открытии, `/nonexistent` — 404;
- тёмная и светлая темы; полноэкранный режим и запоминание отказа от него.
